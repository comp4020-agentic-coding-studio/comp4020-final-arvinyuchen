# Crit 9 reflection

## What was the breakthrough that moved the work forward?

Spots was already real-time: since crit 8 every vote has reached every open
page within a second. The breakthrough was seeing that working wasn't the same
as behaving well. Reading the live layer with the agent, the problem was plain
once I pictured the moment Spots exists for: a group in one room, all voting at
once. Every vote re-sorted the list on every screen, so cards jumped just as
people reached for them, and a keen could land on the wrong place. Two lines of
my own README were pulling against each other. "Deciding together is quick"
wants the ranking live. "Everyone's voice counts the same" means a vote has to
land where it was meant. Of the four options I weighed, I chose to hold each
person's order and offer the new one with a bar. I also made a keen send the
state its button shows, so a double-tap can't undo it. Testing it with two
people voting at once turned up one more thing I'd have missed: the position
numbers were wrong while the order was held, so they're hidden now.

## What did this work change about who I want to be as a software developer?

I want to test a feature in the situation it's actually for, not only check
that it runs. "Votes update live" passed every check I had. It took picturing,
and then simulating, several people at once to see it fail them. I also left
this week's work late: a check on the morning of the cutoff found nothing for
crit 9 on main yet. Next time I want to run that check at the start of the
week, so the decision gets made while there's time to argue with it, not
squeezed in before the deadline.
